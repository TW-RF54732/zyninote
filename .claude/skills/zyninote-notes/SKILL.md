# Zyninote 筆記

Zyninote 是學習用的筆記系統：使用者在 vault 裡寫 `.md`／`.mdx`／`.tsx`，系統負責導覽、目錄、搜尋、反向連結與小抄。你的工作是產出**系統能正確解析**、**放進小抄也讀得懂**的筆記。

每個標題區塊（`##`、`###`…）都是系統的基本單位：目錄、搜尋結果、連結預覽和小抄卡片都以區塊為單位。所以這份 skill 的大部分規則都在講怎麼寫好區塊。

## 1. 先找到 vault 與 app

- **vault**：筆記資料夾，底下直接是各科目資料夾（裡面有 `_subject.md`）。在 app repo 裡就是 `content/`；也可能是任何外部資料夾。
- **app**：`package.json` 的 `name` 是 `zyninote`、有 `src/server/check.ts` 的資料夾。用來跑檢查。

不確定 vault 在哪就問使用者，不要猜。`~/.zyninote/last.json` 記錄了上次開啟的 vault，可以參考。

## 2. 動手前先看現況

```sh
python <skill>/scripts/inventory.py <vault> [subject]
```

會列出每個科目的已註冊 tag、每篇筆記的 order／tags／summary，以及所有標題和 ID。寫之前一定要跑，因為：

- **tag 只能用該科目已註冊的**，或你明確決定要新增的（見第 5 節）。
- **order** 要接在現有章節後面或插在正確位置。
- **連結**要指向真的存在的標題 ID。標 `~` 的 ID 是推算的，連過去之後要靠檢查確認。
- 檔名、標題風格、例子與習題的寫法，要**跟這個科目既有的筆記一致**。科目的慣例優先於這份 skill 的建議。

## 3. 結構規則（系統強制）

```
<vault>/
  _components/            共用互動元件（.tsx）
  <subject>/
    _subject.md           科目設定：title、summary、order、tags（已註冊 tag 清單）
    _cheats.json          小抄，由 app 管理
    ch1-intro.md          筆記，全部平行
    ch2-tcp.mdx
    _Chart.tsx            科目內的元件：底線開頭
    slides.pdf            PDF、圖片等附件可以直接放（或放進 _images/ 這類底線資料夾）
```

- vault 底下只放科目資料夾。科目裡**不能有子資料夾**（違反會報錯）。
- `_` 開頭的都是系統檔，不是筆記。
- 檔名就是網址（`/<subject>/<檔名去副檔名>`）。用小寫英數加 `-`，跟科目既有命名一致（例如 `ch4-congestion.md`）。同名不同副檔名會衝突。
- 新科目：建資料夾＋`_subject.md`（title、summary、order、tags）。

## 4. Frontmatter

```yaml
---
title: TCP 壅塞控制
summary: 慢啟動、壅塞避免與快速恢復
order: 4
tags: [傳輸層]
---
```

| 欄位 | 說明 |
|---|---|
| `title` | 頁面標題。內文**不要**再寫 `# 標題`，內文從 `##` 開始 |
| `summary` | 一句話，出現在科目目錄、搜尋與 AI 閱讀，要具體說出本章涵蓋什麼 |
| `order` | 數字，決定章節順序；沒填的排最後再依檔名排序 |
| `tags` | 陣列，只用本科目已註冊的 tag |
| `links: visible` | 選填，整頁的安靜連結都顯示 |

TSX 筆記用 `export const meta = { title, summary, order, tags: ["a"] }`。`tags` 要寫成**字串陣列字面值**，app 的 tag 管理才改得動。

## 5. Tag

tag 只在科目內有效，`_subject.md` 的 `tags:` 就是註冊表。tag 是使用者用來篩選「主線內容 vs 習題、補充、零散筆記」的工具，亂開 tag 會讓篩選失去意義。

- 優先重用既有 tag。
- 真的需要新 tag 時：把它加進 `_subject.md` 的 `tags`，並在回報裡**明確列出新增了哪些 tag、為什麼**，讓使用者可以否決。
- 不要只為了描述內容而加 tag：搜尋已經能找內文了。

## 6. 寫區塊：要能單獨放進小抄

使用者在任何標題旁按 `+`，那個區塊（含子標題）就成為一張小抄卡片，會被拿出原頁閱讀。所以：

- **每個 `##`／`###` 區塊都要能單獨讀懂。** 不要寫「如上所述」「承上」「前面提到的公式」。需要前文時，用一句話重述，或放連結。
- **一個區塊一個概念。** 標題直接說是什麼（「傳輸延遲」，而不是「第二點」）。太長的區塊拆成子標題。
- **標題不編號**（不要「1.」「一、」「Step 1」）。順序由位置表達，章節順序由 `order` 表達。
- **預設摺疊 `{.fold}`** 用在讀第一遍可以跳過的內容：證明、推導細節、習題解答、記憶法、冷門補充。不要摺主線概念。
- **標題 ID**：會被連結、或可能被連結的標題，加上明確的 `{#id}`（小寫英文加 `-`，例如 `{#slow-start}`）。這樣改標題文字不會弄斷連結和小抄卡片。
- **同一頁重複的標題文字**（每題都有的「解答」「證明」）會產生重複 ID 並觸發警告，所以每個都要給不同的 `{#id}`，例如 `#### 解答 {#ex-chain-solution .fold}`。
- **習題與例子**：跟著科目的既有做法（獨立區塊如「例子：…」、或獨立筆記加習題 tag）。沒有先例時，放在相關概念後面的獨立區塊，解答用 `{.fold}`。

## 7. 選格式

| 需要 | 格式 |
|---|---|
| 文字、公式、表格、Mermaid（大部分筆記） | `.md` |
| 在 Markdown 裡嵌入一兩個互動元件 | `.mdx` |
| 整頁都是互動、或需要用程式產生內容 | `.tsx` |

能用 `.md` 就用 `.md`：最穩定、最好編輯。不要發明自訂語法。

**各格式的完整語法、`.mdx` 的陷阱、`.tsx` 範本和互動元件寫法，見 [references/syntax.md](references/syntax.md)。寫 `.mdx`／`.tsx` 或互動元件前一定要讀。**

最常用的語法：

```md
## 三次握手 {#three-way-handshake}
### 證明 {.fold}

[[ch2-tcp#tcp-flags|TCP 旗標]]      安靜連結：平常像一般文字，按 Ctrl 才顯示
[TCP 旗標](ch2-tcp.mdx#tcp-flags)    顯眼連結
$L/R$、$$ ... $$                     數學（KaTeX）
```mermaid                           圖表
```

連結一律**相對路徑**，不能用 `/` 開頭，也不能 `..` 超出 vault。跨科目寫 `../calculus/ch1-limits#epsilon-delta`。

**安靜還是顯眼？** 順帶提到、讀者不一定要點的概念用安靜連結 `[[...]]`（大多數情況）；讀者「應該去看」的前置知識或延伸閱讀用顯眼連結。

## 8. 寫完一定要檢查

在 app 資料夾執行，**明確指定 vault**（不指定會檢查上次開啟的 vault，不一定是你改的那個）：

```sh
npm run check -- --vault <vault 的絕對路徑>
```

斷鏈、找不到標題、未註冊 tag 都只是**警告**，exit code 仍然是 0。所以要讀輸出：**你改動的檔案不能有任何錯誤或警告**。原本就有的問題不用修，但要在回報時提一句。

沒辦法跑檢查（找不到 app、沒有 node_modules）時，就用 `inventory.py` 重新看一次，手動確認：連結目標和 ID 都存在、tag 都已註冊、沒有子資料夾，並告訴使用者沒有跑正式檢查。

## 9. 不要做的事

- 不要改 `_cheats.json`，除非使用者要求（格式見 syntax.md）。小抄是使用者自己挑的。
- 不要改 `.zyninote/`（快取，可隨時刪）。
- 不要改使用者沒提到的筆記。例外：新增內容後，在相關的既有筆記加連結回來是好的，但要在回報裡列出。
- 改標題文字時注意：沒有明確 `{#id}` 的標題，ID 會跟著變，指向它的連結和小抄卡片會失效。改之前先加上原本的 ID，例如 `## 新標題 {#原本的id}`。

## 常見流程

**把講義／投影片／手寫內容整理成筆記**
1. 跑 inventory，看科目現有章節、tag、命名。
2. 決定放進既有筆記還是新開一篇；新開就決定檔名和 order。
3. 依概念切區塊（不是照投影片頁數切），每個區塊單獨可讀。
4. 公式轉 LaTeX，流程圖轉 Mermaid，證明與解答加 `{.fold}`。
5. 連結到本科目已有的相關區塊；需要時在舊筆記加回連結。
6. 跑檢查。

**補習題**：先看科目怎麼放習題（同頁區塊或獨立筆記＋tag），照做。題目可見，解答 `{.fold}`。

**拆分過長的筆記**：新檔案保留原標題的 ID（加上明確 `{#id}`），再搜尋整個 vault 中指向被移走區塊的連結（`grep -rn "原檔名#" <vault>`），以及 `_cheats.json` 中的 `ref`，一起更新（這種情況可以改 `_cheats.json`，並告知使用者）。

**修問題**：跑檢查，依訊息修正：斷鏈多半是 ID 打錯或標題改過；未註冊 tag 就決定要註冊還是換成既有 tag。

## 回報

完成後簡短說明：改了或新增了哪些檔案、新增的 tag（若有）、檢查結果（0 錯誤 0 警告，或剩下哪些原本就有的問題）。
